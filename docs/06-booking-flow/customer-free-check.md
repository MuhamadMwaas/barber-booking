# فحص العميل الحر — Customer Free Check

> **الملفات:** `app/Services/BookingValidationService.php:260` (`assertCustomerIsFree`)، `app/Support/PhoneNumber.php:1`

---

## 1. القاعدة

> العميل لا يمكن أن يكون في مكانين في نفس الوقت — عند أي مزود، بأي خدمة.

```
هل للعميل موعد آخر يتداخل [start,end)؟
  الحالات المانعة: PENDING + COMPLETED (نفس قاعدة المزود)
  التداخل نصف مفتوح: 10:00-11:00 ثم 11:00 مسموح
```

## 2. هوية العميل

| الشكل | المطابقة |
|-------|----------|
| مسجل | `customer_id` **أو** مفتاح هاتفه |
| ضيف | مفتاح الهاتف فقط |
| ضيف بلا هاتف | لا مطابقة |

**مفتاح الهاتف:** `PhoneNumber::key($phone)` — آخر 9 أرقام بعد تجريد كل ما ليس رقماً — `+49 176 1234567` و `0176 1234567` شخص واحد. المقارنة في PHP لأن التطبيع في SQL غير محمول، والمرشحون محصورون بالمتداخلة مع هذه النافذة فقط فعددهم ضئيل.

## 3. التجاوز

`allow_customer_overlap=true` — يُرفع server-side فقط بعد فحص `force_booking`. منفصل عن `bypass_availability`. سببه أن بعض عمل الصالون متوازٍ فعلاً (مانيكير أثناء تفاعل الصبغة).

> استبدل `validateNoDuplicateBooking()` القديمة التي كانت تسأل "نفس لحظة البداية + خدمة مشتركة" — فتسمح بمتزامن عند مزود آخر وبأي تداخل جزئي (BOOK-06).

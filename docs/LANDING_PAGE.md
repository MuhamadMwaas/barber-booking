## 1. ملخّص ما تم تنفيذه

صفحة هبوط عامة كاملة على `/` مطابقة للتصميم المرفق (أسود/ذهبي)، مع:

| البند | الحالة |
|-------|--------|
| صفحة هبوط `/` بتسعة أقسام مطابقة للتصميم | ✅ |
| صفحة تحميل التطبيق `/app` بنفس الهوية | ✅ |
| صفحات قانونية عامة `/page/{slug}` (Impressum, Datenschutz, AGB) | ✅ |
| إدارة كاملة من Filament — شاشة واحدة بـ 11 تبويباً | ✅ |
| ثلاث لغات (de / en / ar) لكل نص يراه الزائر | ✅ |
| كشف لغة المتصفح تلقائياً + زر تبديل لغة | ✅ |
| دعم RTL كامل للعربية (انعكاس التخطيط والخط) | ✅ |
| مفتاح تشغيل/إيقاف وترتيب لكل قسم | ✅ |
| رفع صور لكل عنصر من لوحة التحكم | ✅ |
| SEO كامل (title / description / Open Graph / hreflang) | ✅ |
| 15 اختباراً آلياً | ✅ |

**ما لم يُنفَّذ عمداً:** لا يوجد قسم أسعار ولا رابط `PREISE` في القائمة — راجع [القسم 15](#15-نقاط-مفتوحة-تحتاج-قرارك).

## 2. القرارات المتّفق عليها

| القرار | ما اخترته | الأثر على التنفيذ |

## 3. المعمارية

```
الزائر
  │
  ├─ SetLocaleFromSession  ← يحدّد اللغة (session → user → متصفح → افتراضي)
  │
  └─ LandingController
        │
        ├─ LandingContent  ← يقرأ الأقسام مرة واحدة (مع كاش) ويحلّ الترجمات
        │
        └─ Blade
             layouts/landing.blade.php
               ├─ landing/partials/navbar.blade.php
               ├─ landing/index.blade.php  → يجمّع الأقسام المفعّلة بالترتيب
               │     ├─ sections/hero.blade.php
               │     ├─ sections/services.blade.php
               │     ├─ sections/features.blade.php
               │     ├─ sections/gallery.blade.php
               │     ├─ sections/cta.blade.php
               │     └─ sections/info.blade.php
               └─ landing/partials/footer.blade.php
```

**مبدأ أساسي:** القوالب لا تلمس Eloquent ولا JSON الخام إطلاقاً. تطلب القيم من `$landing` بمسار نقطي:

```php
$landing->text('hero.title_gold')   // نص مترجم جاهز
$landing->image('hero.image')       // رابط عام أو null
$landing->items('services.items')   // عناصر repeater المفعّلة
$landing->links('navbar.links')     // روابط مع حذف المراسي الميتة
$landing->enabled('gallery')        // مفتاح القسم
$landing->linkUrl('#services')      // مرساة تُحوَّل لرابط مطلق خارج صفحة الهبوط
```

## 4. قاعدة البيانات

### جدول `landing_sections`

هجرة: `database/migrations/2026_08_28_000001_create_landing_sections_table.php`

| العمود | النوع | الوصف |
|--------|-------|-------|
| `id` | bigint | — |
| `key` | string **unique** | معرّف القسم الثابت (`hero`, `services`, …) |
| `is_active` | boolean | مفتاح إظهار القسم |
| `sort_order` | int | ترتيب أقسام الجسم فقط |
| `content` | json | كامل محتوى القسم |
| timestamps | | |

### لماذا JSON وليس أعمدة؟

التصميم فيه **~120 نصاً قابلاً للتحرير** موزّعة على 11 قسماً، بالإضافة إلى ثلاث مجموعات متكرّرة (كروت الخدمات، صور المعرض، صناديق المزايا). نمذجتها علائقياً تعني عشرات الجداول وJOINات لصفحة تُقرأ ككتلة واحدة وتُخزَّن في الكاش. الـ JSON يُكتب من شاشة واحدة ويُقرأ من كنترولر واحد، فلا توجد واجهة استعلام نخسرها.

### شكل النص المترجَم

كل نص يراه الزائر يُخزَّن كخريطة لغات:

```json
{
  "title_gold": { "de": "LOOKUP", "en": "LOOKUP", "ar": "لوك أب" }
}
```

ترتيب الاحتياط عند غياب ترجمة: **اللغة المطلوبة → `fallback_locale` → الألمانية → أول قيمة غير فارغة**.
إضافة لغة رابعة = صفّ في جدول `languages` فقط، بلا هجرة ولا تعديل كود.

## 5. المسارات

| الطريقة | المسار | الاسم | الوصف |
|---------|--------|-------|-------|
| GET | `/` | `landing` | صفحة الهبوط |
| GET | `/app` | `landing.app` | صفحة تحميل التطبيق (تُرجع 404 إذا أُوقف القسم) |
| GET | `/language/{code}` | `landing.language` | تبديل اللغة ثم العودة للصفحة السابقة |
| GET | `/page/{slug}` | `landing.page` | صفحة CMS داخل هوية الموقع |
| GET | `/admin/manage-landing-page` | `filament.admin.pages.manage-landing-page` | شاشة الإدارة |

> `/` كان يعرض `welcome.blade.php` الافتراضية — استُبدل. ملف `welcome.blade.php` باقٍ ولم يُحذف.

### الصفحات القانونية داخل الموقع

التذييل في التصميم يعرض **Impressum | Datenschutz**، والقانون الألماني (TMG § 5) يُلزم بصفحة Impressum على الموقع التجاري. المحتوى موجود أصلاً في `cms_pages` لكنه كان متاحاً للتطبيق عبر API فقط ولمعاينة الأدمن. `LandingController::page()` يعرض نفس البلوكات بهوية الموقع عبر `CmsPageTransformer` — بلا تكرار للمحتوى.

الروابط: `/page/impressum` · `/page/privacy-policy` · `/page/terms-conditions`

#### قالب المستندات القانونية (2026-09-07)

هذه ليست نصوصاً تسويقية: سياسة الخصوصية وحدها **78 بلوكاً في 17 قسماً مرقّماً**. القالب الأول كان يسكبها كلها في عمود واحد بلا أي وسيلة للوصول إلى بند معيّن، فاستُبدل بقالب مكتوب للنصوص الطويلة:

| الملف | الدور |
|-------|-------|
| `app/Services/Landing/LegalDocument.php` | يحوّل حمولة الـ CMS إلى **مستند**: عنوان، فهرس، وصف ميتا، بلوكات مُرساة |
| `resources/views/landing/legal.blade.php` | التخطيط: رأس مستند، فهرس لاصق، مرساة لكل قسم، عرض سطر مقيَّد |

ما يقدّمه القالب: رأس صفحة بعنوان المستند وسطر «آخر تحديث»، فهرس محتويات **لاصق** على الشاشات الكبيرة و`<details>` مطوي على الجوال (بلا JavaScript — صفحة قانونية يجب أن تُقرأ والسكربت معطَّل)، مرساة `#section-N` على كل عنوان، `scroll-mt` يمنع اختفاء العنوان تحت شريط التنقّل الثابت، وروابط للمستندات الشقيقة مع حذف الصفحة الحالية.

**ثلاثة قرارات تستحق التوثيق:**

1. **العنوان يأتي من أول بلوك heading بمستوى h1، لا من `cms_pages.name`.** ذلك العمود نصّي **واحد غير مترجَم** وقيمه المزروعة عربية، وكان يُطبَع كـ `<title>` وكـ `<h1>`. فكان الزائر الألماني يرى عنواناً عربياً RTL فوق صفحة `lang="de" dir="ltr"` — ثم العنوان الألماني الصحيح تحته مباشرة، لأن أول بلوك في كل صفحة عنوان h1 **مترجَم بالكامل**. الآن يُستهلك ذلك البلوك كعنوان ولا يُطبع مرتين، ويبقى `name` احتياطاً أخيراً وتسمية داخلية للأدمن.

2. **المراسي أرقام ترتيبية (`section-7`) لا slug من نصّ العنوان.** الـ slug يختلف بين اللغات، و`Str::slug()` يُفرِغ العنوان العربي تماماً — فرابط إلى بندٍ يُشارَك من الصفحة الألمانية كان سيشير إلى جزء غير موجود في العربية. الرقم الترتيبي هو البند نفسه بكل اللغات، وهو جوهر الاستشهاد ببند.

3. **وصف الميتا يُشتقّ من أول فقرة في الصفحة.** قبلها كانت `/page/*` كلها ترث وصف صفحة الهبوط التسويقي، فكانت ثلاثة مستندات قانونية تُعلن عن قصّات الشعر في نتائج البحث ومعاينات الروابط.

> **مصيدة:** بلوك بلا محتوى خاص (`divider`) يصل بـ `content` ككائن `stdClass` **فارغ** لا مصفوفة فارغة — هذا ما يعيده تدوير `{}` عبر json. فهرسته مباشرةً خطأ قاتل (`Cannot use object of type stdClass as array`)، ويقع على **كل** هذه الصفحات لأن فيها جميعاً فواصل. لذلك `LegalDocument` والقالب يُجريان `(array)` على `content` و`props` قبل أي فهرسة.

**معاينة الأدمن `/admin/cms-preview/{id}` منفصلة تماماً** (`CmsPagePreviewController` ← `admin/cms-preview/show.blade.php`) وهي معاينة الجوال — لم تُمَسّ.

البلوكات غير المعروفة تُتجاهَل بصمت، التزاماً بعقد الـ CMS الموثّق في `CMS_FRONTEND_GUIDE.md`.

## 6. نظام اللغات و RTL

### ترتيب تحديد اللغة

عُدِّل `app/Http/Middleware/SetLocaleFromSession.php`. أول مطابقة تفوز:

1. `locale` في الـ session — اختيار صريح سابق (زر الموقع، لوحة الموظفين، مبدّل Filament)
2. عمود `locale` للمستخدم المسجَّل دخوله
3. **`Accept-Language` من المتصفح** ← جديد
4. اللغة المعلَّمة `is_default` في جدول `languages`
5. `config('app.locale')`

النتيجة تُكتب في الـ session، فيجري الكشف مرة واحدة لكل زائر وتصبح الطلبات التالية قراءة session فقط.

**تفصيل مهم:** `getPreferredLanguage()` يطابق الوسم الكامل، فالمتصفح الذي يعلن `de-DE` لا يطابق `de` عندنا. لذلك نمرّر الرموز مع صيغها الإقليمية الشائعة (`de_DE`, `de_AT`, `de_CH`, `ar_SY`, …) ثم نردّ الناتج إلى الرمز الأساسي.

### زر تبديل اللغة

`resources/views/landing/partials/language-switcher.blade.php` — مبني على `<details>/<summary>` وليس JavaScript، لأن الزائر الذي لا يقرأ اللغة الحالية هو **آخر** من يجب أن يعتمد على تشغيل السكربت. يعمل بالكيبورد ومع تعطيل JS.

### RTL

- `<html dir="rtl">` تلقائياً حسب `config('cms.supported_languages.*.direction')`
- كل قواعد CSS تستخدم **logical properties** (`inline-start/end`, `margin-inline`) فينعكس التخطيط بلا ورقة أنماط منفصلة
- العناصر التي لرسمها اتجاه (القوس الذهبي، أسهم «اعرف المزيد») تُعكس صراحةً بـ `scaleX(-1)`
- خط **Cairo** للعربية، و`letter-spacing` يُصفَّر لأن قيم التباعد اللاتينية تشوّه الخط المتّصل
- حقول العربية في لوحة التحكم تأخذ `dir="rtl"` تلقائياً

## 7. لوحة الإدارة في Filament

**المسار:** لوحة التحكم ← *إدارة المحتوى* ← **صفحة الهبوط**
**الملف:** `app/Filament/Pages/ManageLandingPage.php`

### الأزرار في الأعلى

| الزر | الوظيفة |
|------|---------|
| حفظ التعديلات | يحفظ كل التبويبات دفعةً واحدة (اختصار `Ctrl/Cmd + S`) |
| فتح الصفحة | يفتح `/` في تبويب جديد |
| فتح صفحة التطبيق | يفتح `/app` في تبويب جديد |
| مسح الذاكرة المؤقتة | تفريغ يدوي للكاش |

### بنية حالة النموذج

مطابقة تماماً لشكل التخزين، فلا توجد طبقة تحويل بين الشاشة والجدول:

```
data.<section key>.is_active
data.<section key>.sort_order
data.<section key>.content.<field>[.<locale>]
```

### مزايا الشاشة

- **تبويب لكل قسم** (11 تبويباً)، والتبويب المُطفأ يحمل علامة `✕`
- **مفتاح إظهار + ترتيب** لكل قسم من أقسام الجسم
- **حقل لكل لغة مفعّلة** جنباً إلى جنب — تُبنى من جدول `languages` ديناميكياً
- **Repeaters** قابلة للسحب والنسخ والطي، وعنوان كل عنصر مطوي يعرض نصّه الفعلي
- **منتقي أيقونات** من 40 أيقونة مدمجة
- **رفع صور** لكل عنصر
- **إنشاء تلقائي للأقسام الناقصة** عند فتح الشاشة — يكفي إضافة مفتاح إلى `LandingSection::KEYS` ليظهر تبويبه

## 8. الأقسام وحقولها

### الأقسام الهيكلية (لا مفتاح إظهار)

| المفتاح | المحتوى |
|---------|---------|
| `brand` | الشعار، أيقونة المتصفح، اسم العلامة، اللاحقة، العبارة التعريفية |
| `seo` | عنوان المتصفح، وصف الميتا، الكلمات المفتاحية، صورة المشاركة |
| `navbar` | نص الزر ورابطه، إظهار مبدّل اللغة، مصفوفة الروابط |

### أقسام الجسم (مفتاح إظهار + ترتيب)

| المفتاح | الترتيب | المحتوى |
|---------|---------|---------|
| `hero` | 10 | تسمية علوية، عنوان ذهبي، عنوان أبيض، وصف، صورة + وصفها، زرّان، 3 شارات |
| `services` | 20 | تسمية، عنوان، وصف، نص رابط الكرت، **Repeater**: صورة + أيقونة + عنوان + وصف + رابط + إظهار |
| `features` | 30 | تسمية، عنوان، وصف، زر، **Repeater**: أيقونة + عنوان + وصف |
| `gallery` | 40 | تسمية، عنوان، زر، **Repeater**: صورة + وصف بديل + تعليق + **بطاقة عريضة** + إظهار |
| `cta` | 50 | أيقونة، عنوان، وصف، نص الزر، رابط الزر |
| `info` | 60 | **Repeater**: أيقونة + تسمية + قيمة + رابط · وعنوان التواصل + **Repeater** روابط التواصل |

### التذييل وصفحة التطبيق

| المفتاح | المحتوى |
|---------|---------|
| `footer` | عبارة + سطر ختام · عمودا روابط · نشرة بريدية · سطر حقوق + روابط قانونية |
| `app_page` | تسمية، عنوان، وصف، رابطا المتجرين ونصّاهما، ملاحظة «قريباً»، صورة الهاتف، QR + نصّه، **Repeater** مزايا، **Repeater** خطوات |

### ملاحظات سلوكية مهمة

- **البطاقة العريضة في المعرض:** التصميم يُبرز البطاقة الوسطى. الإبراز محتوى وليس تخطيطاً، لذا كل صورة تحمل مفتاح `is_wide` والأدمن يقرّر. البطاقة العريضة **تتمدّد** لارتفاع الصف بدل حساب نسبة أبعاد خاصة، لأن أي نسبة محسوبة ستنحرف ببضعة بكسلات مع تغيّر الفجوة بين الأعمدة.
- **الروابط الميتة:** أي رابط مرساة (`#gallery`) يُحذف تلقائياً من شريط التنقل والتذييل عند إيقاف القسم الذي يشير إليه.
- **المراسي خارج صفحة الهبوط:** في `/app` و`/page/*` تتحوّل `#services` إلى `/#services` تلقائياً عبر `linkUrl()`.
- **النشرة البريدية:** النظام **لا يخزّن مشتركين**. لذلك يظهر النموذج فقط إذا أُدخل رابط نموذج مزوّد خارجي (Mailchimp / Brevo / CleverReach). بدونه يظهر زر بريد بسيط — لأن عرض حقل يبتلع العنوان بصمت أسوأ من عدم عرضه.
- **روابط المتاجر:** ما دامت فارغة تعرض `/app` ملاحظة توضيحية بدل زر معطّل.

## 12. أخطاء اكتُشفت وأُصلحت أثناء التنفيذ

أربعة أخطاء حقيقية ظهرت أثناء الاختبار، وكلها كانت ستصل للإنتاج:

### ١. الأقسام لا تظهر إطلاقاً — `Eloquent\Collection::only()`

`orderedBodyKeys()` كانت ترجع مصفوفة فارغة والصفحة تخرج بلا أي قسم.

السبب: `Illuminate\Database\Eloquent\Collection` **يعيد تعريف** `only()` ليفلتر حسب **المفتاح الأساسي** للنماذج، متجاهلاً مفاتيح `keyBy()` تماماً. الحل: `->toBase()` بعد `keyBy('key')`.

### ٢. الحفظ من لوحة التحكم **يمسح كل الصور**

`mount()` كانت تُسند `$this->data` مباشرة بدل `$this->form->fill()`. الإسناد المباشر يتخطّى كل دوال hydration الخاصة بالمكوّنات، و`FileUpload` تحديداً تخزّن مساراً نصياً لكنها تعمل داخلياً بمصفوفة — فكان أول حفظ ينهار بـ:

```
BaseFileUpload::getValidationRules(): Argument #2 ($value) must be of type array, string given
```

ثم — بعد إصلاح ذلك — تبيّن أن `FileUpload` تتحقق من وجود الملف على قرص `public`، والمسارات المزروعة (`/image/landing/salon.png`) ملفات تحت `public/` مباشرة وليست على ذلك القرص، فكانت تُسقَط عند التحميل وتُحفَظ `null`. لذلك **يزرع السييدر حقول الصور فارغة** والقوالب تعرض الأصول المرفقة كاحتياط. أُضيف اختبار انحدار لهذه الحالة.

### ٣. محتوى قديم بعد الحفظ — `Route::getController()` يحتفظ بالكنترولر

`LandingContent` كانت مُحقَّنة في باني `LandingController`. المشكلة أن `Illuminate\Routing\Route::getController()` **يحتفظ بنسخة الكنترولر على كائن المسار**، والمسارات تعيش طوال عمر التطبيق — فأي خدمة مُحقَّنة في الباني تُشارَك بين كل الطلبات التي تخدمها العملية. و`LandingContent` تحفظ كامل محتوى الأقسام في ذاكرتها.

تحت PHP-FPM يختفي الأثر (عملية لكل طلب)، لكنه تحت **Octane** كان سيقدّم محتوى ما قبل آخر حفظ حتى إعادة التشغيل. الحل: حلّ الخدمة داخل كل action، وربطها كـ `bind` غير مشترك — لا `singleton` ولا `scoped` (الأخيرة لا تُفرَّغ إلا بفلاش الطلب في وقت تشغيل دائم، وهو ما لا يفعله PHP-FPM ولا مشغّل الاختبارات).

### ٤. روابط ميتة في التذييل وفي `/app`

- روابط التذييل التي تشير لقسم مُطفأ كانت تبقى موجودة. الفلترة نُقلت إلى `LandingContent::links()` ويستعملها شريط التنقل والتذييل معاً.
- المراسي في `/app` و`/page/*` كانت تشير إلى أقسام غير موجودة على تلك الصفحة. أُضيفت `linkUrl()` التي تحوّلها إلى `/#services` خارج صفحة الهبوط.
